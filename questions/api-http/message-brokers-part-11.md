## 38. Что отвечать QA/SDET про тестирование брокеров

### Хороший универсальный ответ:

Я бы тестировал брокерную интеграцию на нескольких уровнях. На уровне producer-а проверил бы, что публикуется корректное сообщение в нужный topic/queue с правильным payload, headers, key/routing key. На уровне consumer-а проверил бы обработку валидных, невалидных и дублирующихся сообщений, ack/nack, retry, DLQ и идемпотентность. На end-to-end уровне проверил бы полный бизнес-флоу: действие через API приводит к событию, событие обрабатывается consumer-ом, и результат появляется в БД или другом сервисе. Для асинхронности использовал бы polling/wait_until с timeout, а не простые sleep.  

## 39. Частые ошибки в тестах с брокерами

Ошибка 1: использовать sleep  

### Плохо:

send_message()  
sleep(10)  
assert result_exists()  

Лучше:  

send_message()  
wait_until(result_exists, timeout=10)  
Ошибка 2: не чистить тестовые данные  

Если topic/queue общие, один тест может влиять на другой.  

Решения:  

уникальные ids;  
отдельные test topics/queues;  
очистка после теста;  
isolated environment;  
docker/testcontainers.  
Ошибка 3: не проверять дубли  

Многие проверяют только happy path.  

Но в брокерах дубли — нормальная ситуация.  

Ошибка 4: не проверять DLQ  

Если не тестировать DLQ, poison message может сломать очередь в проде.  

Ошибка 5: проверять только факт сообщения  

Недостаточно проверить:  

Сообщение появилось  

Нужно проверить:  

правильный topic/queue;  
payload;  
headers;  
key/routing key;  
schema;  
timestamp;  
correlation_id;  
обработку consumer-ом.  

## 40. Мини-шпаргалка по формулировкам

Producer  

Producer — сервис, который публикует сообщение в broker.  

Consumer  

Consumer — сервис, который читает и обрабатывает сообщение.  

Topic  

Topic — логический канал сообщений, например orders.created.  

Queue  

Queue — очередь, из которой сообщение обычно обрабатывается одним consumer-ом.  

Partition  

Partition — часть Kafka topic-а для масштабирования и параллельной обработки.  

Offset  

Offset — позиция сообщения в Kafka partition.  

Consumer group  

Группа consumers, которые совместно читают topic. Внутри group одна partition назначается одному consumer-у.  

Ack  

Подтверждение успешной обработки сообщения.  

Nack  

Сообщение не обработано, его нужно переотправить, ретраить или отправить в DLQ.  

DLQ  

Очередь для сообщений, которые не удалось обработать.  

Retry  

Повторная попытка обработки сообщения.  

Lag  

Отставание consumer-а от последних сообщений.  

Idempotency  

Возможность безопасно обработать одно и то же сообщение несколько раз.  

Retention  

Время или объём хранения сообщений в брокере.
