## 61. Wireshark

Wireshark — GUI-инструмент для анализа сетевого трафика.  

Можно смотреть:  

TCP handshake;  
HTTP-запросы;  
DNS-запросы;  
TLS handshake;  
retransmissions;  
reset packets;  
latency;  
ошибки соединений.  
Для QA  

Полезно, если нужно понять:  

запрос реально ушел или нет;  
что именно отправляет клиент;  
какой ответ приходит;  
где соединение рвется;  
есть ли ретраи;

## 62. Маршрутизация

Маршрутизация — процесс выбора пути для пакета.  

Посмотреть маршруты:  

ip route  

### Пример:

default via 192.168.1.1 dev wlan0  
192.168.1.0/24 dev wlan0 proto kernel scope link src 192.168.1.10  
default gateway  

Default gateway — куда отправлять пакеты, если адрес не из локальной сети.  

На домашнем ноутбуке это обычно роутер.  

### Как объяснить

Если хост назначения не находится в локальной сети, пакет отправляется на default gateway, а дальше маршрутизируется другими роутерами.  

## 63. MTU

MTU — Maximum Transmission Unit.  

Это максимальный размер пакета на интерфейсе.  

Обычно Ethernet MTU:  

1500 bytes  

Если MTU настроен неправильно, могут быть странные проблемы:  

маленькие запросы работают;  
большие зависают;  
VPN работает нестабильно;  
TLS/HTTP запросы подвисают.  

Посмотреть:  

ip link  

## 64. Latency, bandwidth, throughput

Latency  

Задержка.  

Сколько времени пакет идет туда-обратно  

Измеряется в ms.  

Bandwidth  

Пропускная способность канала.  

Сколько данных теоретически можно передать  

Например:  

100 Mbps  
1 Gbps  
Throughput  

Фактическая скорость передачи данных.  

Она может быть ниже bandwidth из-за:  

потерь;  
congestion;  
ограничений приложения;  
CPU;  
диска;  
TLS;  
proxy;  
БД.  

## 65. Packet loss

Packet loss — потеря пакетов.  

Может приводить к:  

ретраям;  
росту latency;  
обрывам соединений;  
медленной работе API;  
проблемам в real-time сервисах.  

Проверять:  

ping example.com  

Более удобно:  

mtr example.com  

## 66. Keep-Alive

HTTP keep-alive позволяет переиспользовать TCP-соединение для нескольких HTTP-запросов.  

Без keep-alive:  

каждый запрос -> новое TCP-соединение  

С keep-alive:  

одно TCP-соединение -> много HTTP-запросов  

### Плюсы:

меньше overhead;  
быстрее;  
меньше TCP handshakes.  

## 67. Таймауты

Таймауты — критически важная тема для QA.  

Виды таймаутов  
Таймаут	Что значит  
Connection timeout	не удалось установить соединение  
Read timeout	соединение есть, но ответа нет  
Write timeout	не удалось отправить данные  
Idle timeout	соединение простаивает слишком долго  
Gateway timeout	proxy не дождался backend  
В requests на Python  
import requests  

response = requests.get(  
    "https://example.com",  
    timeout=(3, 10),  
)  

Где:  

3 — connect timeout  
10 — read timeout  
На собесе  

Я бы разделял connect timeout и read timeout. Первый означает, что не удалось установить соединение, второй — соединение установлено, но сервер не отдал ответ вовремя.  

## 68. Retries

Retries — повторные попытки запроса.  

Используются при временных ошибках:  

timeout;  
502;  
503;  
504;  
connection reset;  
временная недоступность.  

Но опасно ретраить неидемпотентные операции.  

Например  

Безопаснее ретраить:  

GET  
PUT  
DELETE — осторожно, но обычно можно  

Опасно ретраить:  

POST /payments  
POST /orders  

Если нет idempotency key.  

## 69. Idempotency Key

Idempotency key помогает безопасно повторять POST-запросы.  

### Пример:

POST /payments  
Idempotency-Key: 123e4567  

Если клиент повторит запрос с тем же ключом, сервер не должен создать второй платеж.  

Для QA  

Нужно тестировать:  

повторный запрос с тем же ключом;  
повторный запрос с другим ключом;  
поведение при timeout после успешной обработки;  
конкурентные запросы с одним ключом.  

## 70. Rate limiting

Rate limiting ограничивает количество запросов.  

### Пример:

100 requests per minute  

Если лимит превышен:  

429 Too Many Requests  

### Часто есть header:

Retry-After: 60  
Что тестировать  
лимит действительно работает;  
после истечения окна запросы снова проходят;  
разные пользователи не влияют друг на друга;  
правильный статус 429;  
есть понятная ошибка;  
есть Retry-After;  
авторизованные/анонимные лимиты отличаются.
