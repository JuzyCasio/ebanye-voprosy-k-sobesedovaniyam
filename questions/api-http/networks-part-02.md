## 8. MAC-адрес

MAC-адрес — это адрес сетевой карты на канальном уровне.  

### Пример:

00:1A:2B:3C:4D:5E  

IP нужен для маршрутизации между сетями.  
MAC нужен для доставки внутри локальной сети.  

### Как связаны IP и MAC

Для связи IP → MAC используется ARP.  

## 9. ARP

ARP — Address Resolution Protocol.  

Он нужен, чтобы узнать MAC-адрес устройства по IP внутри локальной сети.  

### Пример:

Кто имеет IP 192.168.1.10?  
Ответ: 192.168.1.10 имеет MAC 00:1A:2B:3C:4D:5E  
Команды  
arp -a  
ip neigh  
На собеседовании  

ARP работает в локальной сети и позволяет по IP-адресу узнать MAC-адрес устройства, чтобы отправить Ethernet-фрейм.  

## 10. TCP и UDP

Это один из самых частых блоков.  

TCP  

TCP — надежный протокол транспортного уровня.  

Особенности:  

устанавливает соединение;  
гарантирует доставку;  
гарантирует порядок пакетов;  
умеет повторно отправлять потерянные данные;  
контролирует поток данных;  
медленнее UDP из-за дополнительных проверок.  

Используется для:  

HTTP/HTTPS  
SSH  
FTP  
SMTP  
PostgreSQL  
MySQL  
Kafka  
RabbitMQ  
Redis  
UDP  

UDP — более простой и быстрый протокол.  

Особенности:  

не устанавливает соединение;  
не гарантирует доставку;  
не гарантирует порядок;  
меньше overhead;  
подходит для real-time сценариев.  

Используется для:  

DNS  
VoIP  
стриминг  
онлайн-игры  
DHCP  
QUIC/HTTP/3  
TCP vs UDP  
Критерий	TCP	UDP  
Соединение	Есть	Нет  
Надежность	Гарантирует доставку	Не гарантирует  
Порядок данных	Гарантирует	Не гарантирует  
Скорость	Обычно медленнее	Обычно быстрее  
Примеры	HTTP, SSH, БД	DNS, стриминг, игры  
Хороший ответ на собесе  

TCP используется там, где важна надежность и порядок доставки: HTTP, базы данных, SSH. UDP используется там, где важнее скорость и допустимы потери: DNS, звонки, стриминг, игры. TCP устанавливает соединение и подтверждает доставку, UDP просто отправляет датаграммы без гарантии.  

## 11. TCP Handshake

TCP устанавливает соединение через 3-way handshake.  

1. Client -> Server: SYN  
2. Server -> Client: SYN-ACK  
3. Client -> Server: ACK  

После этого соединение считается установленным.  

### Как объяснить

TCP handshake нужен, чтобы клиент и сервер договорились о соединении и начальных параметрах передачи данных.  

## 12. Закрытие TCP-соединения

Обычно закрытие происходит через FIN/ACK:  

Client -> FIN  
Server -> ACK  
Server -> FIN  
Client -> ACK  

Но иногда соединение может быть резко сброшено через RST.  

## 13. TCP состояния

### Команда:

ss -tan  

### Примеры состояний:

Состояние	Значение  
LISTEN	процесс слушает порт  
ESTABLISHED	соединение установлено  
SYN-SENT	клиент отправил SYN  
SYN-RECEIVED	сервер получил SYN  
TIME-WAIT	ожидание после закрытия  
CLOSE-WAIT	удаленная сторона закрыла соединение, локальная еще нет  
Что важно  

Если много TIME-WAIT — не всегда проблема, это нормальное состояние после закрытия соединений.  

Если много CLOSE-WAIT — возможно, приложение неправильно закрывает соединения.  

## 14. Порт

Порт — это номер приложения/процесса на хосте.  

IP указывает на машину.  
Порт указывает на конкретный сервис внутри машины.  

### Пример:

192.168.1.10:5432  

Здесь:  

192.168.1.10 — IP  
5432 — порт PostgreSQL  
Диапазоны портов  
Диапазон	Назначение  
0–1023	well-known ports  
1024–49151	registered ports  
49152–65535	dynamic/ephemeral ports

## 16. Что значит “порт открыт”

Порт открыт — значит на этом порту есть процесс, который слушает входящие соединения.  

Проверить:  

ss -tulpen  

Или:  

lsof -i :8080  

### Пример:

ss -tulpen | grep 8080  

Если видим LISTEN, значит процесс слушает порт.  

## 17. Connection refused

Ошибка:  

Connection refused  

Означает:  

хост доступен;  
но на нужном порту никто не слушает;  
либо firewall активно отклоняет соединение.  

### Пример:

curl http://localhost:8080  

А сервис не запущен.  

### Как ответить на собесе

Connection refused обычно означает, что соединение до хоста дошло, но на указанном порту нет процесса, который принимает соединения, либо соединение отклоняется firewall.
