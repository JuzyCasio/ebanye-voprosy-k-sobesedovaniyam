## Python компилируемый или интерпретируемый?

**Короткий ответ**

Обычно Python называют интерпретируемым языком, но это упрощение. CPython компилирует исходный код в байткод, а затем виртуальная машина выполняет этот байткод.

```text
source.py → bytecode → Python virtual machine
```

Байткод может кешироваться в `.pyc` внутри `__pycache__`, чтобы не повторять часть работы при следующем импорте.

Ответ зависит от реализации:

- CPython исполняет байткод своей виртуальной машиной;
- PyPy использует JIT-компиляцию;
- существуют реализации для JVM и .NET.

Поэтому корректный ответ: язык не обязан быть только «компилируемым» или только «интерпретируемым»; конкретный процесс определяет реализация.

## Что такое CPython?

CPython — основная реализация Python, написанная преимущественно на C. Когда говорят о GIL, подсчёте ссылок, внутреннем устройстве `dict` или байткоде, часто описывают именно CPython, а не обязательные свойства всех реализаций языка.

Это уточнение полезно на собеседовании:

> Спецификация гарантирует поведение языка, а детали памяти и производительности могут зависеть от CPython и его версии.

## Как устроены переменные и объекты в памяти?

Имя переменной связывается с объектом. Объект содержит тип, значение и служебные данные реализации.

```python
first = [1, 2]
second = first
```

Присваивание не копирует список: оба имени указывают на один объект.

`id(obj)` возвращает идентичность объекта на время его жизни. В CPython она обычно связана с адресом памяти, но полагаться на это как на общее правило языка нельзя.

```python
first is second  # True
id(first) == id(second)  # True
```

## Как устроен список?

На уровне CPython список похож на динамический массив ссылок на объекты.

Следствия:

- доступ по индексу — `O(1)`;
- элементы могут иметь разные типы, потому что хранятся ссылки;
- `append()` амортизированно `O(1)`;
- вставка или удаление в начале/середине — `O(n)` из-за сдвига ссылок;
- список обычно резервирует дополнительную ёмкость, поэтому не перевыделяет память при каждом `append`.

```python
items = [object_a, object_b, object_c]
```

Ячейки массива имеют постоянный размер, потому что содержат ссылки, а не сами объекты произвольного размера.

## Как в памяти отличаются `list` и `tuple`?

Оба контейнера хранят ссылки на элементы. Но:

- список изменяем и поддерживает запас ёмкости для роста;
- кортеж имеет фиксированный размер после создания;
- кортеж обычно требует меньше памяти;
- неизменность кортежа позволяет хешировать его, если хешируемы элементы.

Конкретные размеры являются деталями реализации и версии, поэтому на собеседовании важнее объяснить модель, а не запоминать количество байтов.

## Почему индексация начинается с нуля?

Для массивоподобной структуры индекс удобно понимать как смещение от начала:

```text
address(element) = start + index × element_size
```

Первый элемент находится со смещением `0`, второй — `1` и так далее. Это исторически распространённая модель, унаследованная многими языками. В Python она также удобно согласуется с полуоткрытыми диапазонами:

```python
values[start:stop]
len(values[:n]) == n
```

## Что такое сборка мусора?

CPython в основном освобождает объекты с помощью подсчёта ссылок. Когда счётчик ссылок становится нулём, объект обычно уничтожается сразу.

```python
value = SomeObject()
other = value

del value  # одна ссылка остаётся
del other  # объект может быть освобождён
```

Подсчёт ссылок не справляется с циклами:

```python
first.ref = second
second.ref = first
```

Для обнаружения недостижимых циклов CPython использует циклический garbage collector из модуля `gc`.

Практические выводы:

- не следует рассчитывать на момент вызова `__del__`;
- внешние ресурсы нужно закрывать через `with`, а не ждать GC;
- циклы с финализаторами и большие графы объектов могут усложнять освобождение памяти;
- утечка может быть не только «неосвобождённой памятью», но и ненужной живой ссылкой в кеше или глобальной коллекции.

## Что такое интернирование?

Интерпретатор может переиспользовать некоторые неизменяемые объекты, например отдельные строки или небольшие числа, чтобы экономить память и ускорять операции.

```python
first = "python"
second = "python"

first is second  # может быть True, но это не контракт для сравнения значений
```

Интернирование — причина, по которой ошибочный код с `is` иногда случайно работает. Значения сравнивают через `==`.

## Как проверить тип объекта?

```python
type(value) is int
isinstance(value, int)
```

- `type(value) is SomeType` требует точного типа;
- `isinstance(value, SomeType)` учитывает наследование;
- `isinstance(value, (int, float))` проверяет несколько типов.

В полиморфном коде обычно предпочтительнее `isinstance` или проверка требуемого поведения. Для тестов точная проверка `type(...) is ...` уместна, если подкласс действительно недопустим.

## Как проверить изменяемость объекта?

Универсальной встроенной функции `is_mutable()` нет.

Практически используют:

- знание контракта конкретного типа;
- проверку документации;
- наличие операций изменения — только как подсказку;
- попытку изменить объект в контролируемом тесте.

Хешируемость не является точным тестом изменяемости. Большинство изменяемых встроенных контейнеров нехешируемы, но пользовательский изменяемый объект может иметь хеш по идентичности.
