## Чем конкурентность отличается от параллелизма?

- **Конкурентность** — несколько задач находятся в процессе выполнения и перекрываются по времени.
- **Параллелизм** — несколько задач физически выполняются одновременно, например на разных ядрах CPU.

Один поток с `asyncio` может конкурентно обслуживать множество сетевых операций, переключаясь во время ожидания. Несколько процессов могут выполнять CPU-задачи параллельно на разных ядрах.

## Что такое поток и процесс?

| Процесс | Поток |
|---|---|
| отдельное адресное пространство | разделяет память процесса |
| тяжелее создавать и переключать | обычно легче |
| данные нужно сериализовать или помещать в shared memory | объекты доступны всем потокам процесса |
| сбой сильнее изолирован | ошибка может повредить общее состояние |
| подходит для CPU-bound параллелизма | часто подходит для блокирующего I/O |

Потоки одного процесса разделяют глобальные переменные и объекты, поэтому нуждаются в синхронизации. Процессы изолированы, но обмен между ними сложнее.

## Что такое GIL?

**Короткий ответ**

GIL (*Global Interpreter Lock*) в обычной сборке CPython позволяет только одному потоку одновременно выполнять Python-байткод внутри одного интерпретатора.

Следствия:

- потоки не дают обычному Python-коду линейного ускорения CPU-bound вычислений;
- потоки полезны для I/O-bound работы, потому что во время многих операций ввода-вывода GIL освобождается;
- C-расширения также могут освобождать GIL на тяжёлых вычислениях;
- GIL не устраняет race conditions и не делает составные операции автоматически потокобезопасными.

### У GIL есть исключения?

Начиная с Python 3.13 существуют официальные **free-threaded** сборки CPython, где GIL можно отключить. Они пока являются отдельным вариантом запуска, а сторонние расширения могут включать GIL обратно. На собеседовании важно уточнять: речь об обычной сборке CPython или о free-threaded.

## Являются ли потоки Python настоящими потоками ОС?

Да. `threading.Thread` в CPython работает поверх нативных потоков операционной системы. GIL ограничивает одновременное выполнение Python-байткода, но не превращает потоки в «ненастоящие».

Не следует путать их с:

- задачами `asyncio`, которые планируются event loop;
- green threads/greenlets, которые планирует библиотека в пользовательском пространстве;
- процессами `multiprocessing`.

## Когда использовать потоки, процессы или asyncio?

| Задача | Обычно подходит |
|---|---|
| много блокирующих HTTP-запросов | потоки |
| библиотека уже предоставляет async API | `asyncio` |
| CPU-bound вычисления на чистом Python | процессы |
| несколько независимых тестов | отдельные worker-процессы |
| простая последовательная работа | ничего из перечисленного |

### I/O-bound

Большая часть времени уходит на ожидание сети, диска, БД или внешнего сервиса. Потоки и `asyncio` позволяют выполнять другую работу во время ожидания.

### CPU-bound

Большая часть времени уходит на вычисления. Для обычной сборки CPython чаще используют процессы или нативную библиотеку, которая освобождает GIL.

Выбор зависит не только от типа задачи, но и от API используемых библиотек, сложности кода и требуемой изоляции.

## Что такое race condition?

Race condition возникает, когда результат зависит от порядка выполнения конкурентных операций над общим состоянием.

```python
# Эта операция логически состоит из чтения, вычисления и записи.
counter += 1
```

Даже при наличии GIL переключение может произойти между операциями байткода, а I/O и C-код могут освобождать блокировку. Поэтому общее изменяемое состояние нужно защищать или исключать архитектурно.

В автотестах типичные источники гонок:

- общий тестовый пользователь;
- один файл для результатов;
- общий браузер или API-клиент с изменяемым состоянием;
- одинаковые имена создаваемых сущностей;
- очистка данных одного теста другим.

## Какие средства синхронизации существуют?

В `threading`:

- `Lock`, `RLock`;
- `Semaphore`;
- `Event`;
- `Condition`;
- `Barrier`;
- потокобезопасная `queue.Queue`.

```python
from threading import Lock

lock = Lock()

with lock:
    update_shared_state()
```

У `multiprocessing` есть аналоги для процессов. У `asyncio` — `asyncio.Lock`, `Event`, `Semaphore`, `Queue`, но они предназначены для задач одного event loop, а не для синхронизации потоков ОС.

## Что такое `async` и `await`?

`async def` объявляет корутинную функцию. Её вызов создаёт объект coroutine, но не выполняет тело до конца сам по себе.

`await` приостанавливает текущую корутину, пока ожидаемая операция не завершится, и позволяет event loop выполнять другие готовые задачи.

```python
import asyncio


async def fetch_user(client, user_id):
    response = await client.get(f"/users/{user_id}")
    return response.json()


async def main(client):
    users = await asyncio.gather(
        fetch_user(client, 1),
        fetch_user(client, 2),
    )
    return users


asyncio.run(main(client))
```

`await` не делает блокирующую функцию асинхронной. `time.sleep()` блокирует поток; в async-коде нужен `await asyncio.sleep()` или вынос блокирующей функции в executor.

## Как event loop выполняет задачи?

Event loop:

1. хранит готовые задачи и зарегистрированные I/O-события;
2. запускает готовую корутину;
3. когда она доходит до `await`, задача приостанавливается;
4. loop выполняет другую готовую задачу;
5. после завершения ожидаемой операции возвращает первую задачу в очередь.

В одном потоке только одна корутина выполняет Python-код в конкретный момент. Конкурентность появляется благодаря добровольным точкам переключения `await`.

CPU-bound цикл без `await` заблокирует event loop.

## Как конкурентность применяется в AQA?

### Параллельный прогон тестов

Pytest-плагин `pytest-xdist` обычно запускает worker-процессы. Это ускоряет независимые тесты и обеспечивает лучшую изоляцию, чем потоки.

### Конкурентные запросы

Потоки или async-клиент полезны для:

- нагрузочных проверок небольшого масштаба;
- проверки идемпотентности;
- воспроизведения гонок;
- одновременного создания или изменения сущности;
- ожидания нескольких независимых внешних систем.

### Проверка асинхронного приложения

Async-тесты нужны, если тестируемый клиент и фикстуры асинхронные. Для Pytest обычно используют подходящий плагин, например `pytest-asyncio`.

### Важная граница

Функциональные автотесты не заменяют специализированный нагрузочный инструмент. Для серьёзной нагрузки важны модель пользователей, генерация трафика, метрики, распределённый запуск и контролируемая среда.

## Чем параллельный запуск тестов отличается от потоков внутри теста?

При параллельном запуске разные тесты распределяются по worker-процессам. Каждый worker имеет собственный интерпретатор и память.

При создании потоков внутри одного теста несколько потоков совместно выполняют один сценарий и разделяют память. Это нужно, когда сама проверка требует одновременности.

Перед параллелизацией набора тестов нужно обеспечить:

- независимые тестовые данные;
- уникальные имена и идентификаторы;
- отсутствие зависимости от порядка;
- раздельные временные файлы;
- корректную область жизни фикстур;
- безопасную очистку;
- отсутствие общего браузера между worker-ами.
