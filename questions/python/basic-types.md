# Основные типы, типизация и изменяемость

## Какие основные типы существуют в Python?

**Короткий ответ**

Основные встроенные типы можно разделить на несколько групп:

- числа: `int`, `float`, `complex`;
- логический тип: `bool`;
- текст: `str`;
- последовательности: `list`, `tuple`, `range`;
- отображения: `dict`;
- множества: `set`, `frozenset`;
- бинарные данные: `bytes`, `bytearray`, `memoryview`;
- отсутствие значения: `None`, имеющее тип `NoneType`.

| Группа | Типы | Пример |
|---|---|---|
| целые и вещественные числа | `int`, `float` | `10`, `3.14` |
| комплексные числа | `complex` | `2 + 3j` |
| логические значения | `bool` | `True`, `False` |
| текст | `str` | `"hello"` |
| последовательности | `list`, `tuple`, `range` | `[1, 2]`, `(1, 2)`, `range(3)` |
| отображения | `dict` | `{"id": 10}` |
| множества | `set`, `frozenset` | `{1, 2}`, `frozenset({1, 2})` |
| бинарные данные | `bytes`, `bytearray`, `memoryview` | `b"abc"` |
| отсутствие значения | `NoneType` | `None` |

`bool` является подклассом `int`: `True == 1` и `False == 0`. Это особенность системы типов Python, но обычно логические значения не стоит использовать вместо чисел.

## Что означает динамическая типизация?

**Короткий ответ**

В Python у переменной нет навсегда закреплённого типа. Во время выполнения программы она может сначала ссылаться на число, а потом, например, на строку. Тип принадлежит самому объекту.

Совместимость типов при выполнении операции проверяется во время работы программы:

```python
value = 10
value = "ten"  # допустимо: теперь value ссылается на строку

"10" + 5  # TypeError возникнет во время выполнения
```

При **статической типизации** тип переменной или выражения известен и проверяется статическим анализатором до запуска программы. Python остаётся динамически типизированным языком даже при использовании аннотаций.

Аннотация типа сама по себе не меняет поведение интерпретатора:

```python
age: int = 30
age = "thirty"  # интерпретатор разрешит, но статический анализатор предупредит
```

Аннотации помогают людям, IDE и инструментам вроде `mypy` или `pyright`, но сами по себе не запрещают присвоить значение другого типа.

### А что тогда означает сильная типизация?

Динамическая/статическая и сильная/слабая типизация — разные характеристики.

Python часто называют языком с **сильной типизацией**, потому что он обычно не смешивает несовместимые типы автоматически: например, строку и число нельзя сложить без явного преобразования. Но у терминов «сильная» и «слабая типизация» нет единого строгого определения, поэтому для ответа про динамическую типизацию они не нужны.

## Что такое изменяемые и неизменяемые объекты?

**Короткий ответ**

**Изменяемый объект** можно изменить после создания. **Неизменяемый объект** после создания изменить нельзя.

Если кажется, что мы «изменили» неизменяемый объект, на самом деле был создан другой объект, а переменная стала ссылаться на него.

### Изменяемые встроенные типы

- `list`;
- `dict`;
- `set`;
- `bytearray`.

`bytearray` — изменяемая последовательность байтов:

```python
data = bytearray(b"cat")
data[0] = ord("b")

print(data)  # bytearray(b"bat")
```

Не следует путать его с `bytes`: объект `bytes` неизменяемый.

Возможность изменять данные через `memoryview` зависит от того, доступен ли исходный буфер для записи, поэтому для базового ответа на собеседовании его лучше рассматривать отдельно.

### Неизменяемые встроенные типы

- **числа:** `int`, `float`, `complex`;
- **логические значения:** `bool`;
- **строки:** `str`;
- **кортежи:** `tuple`;
- **неизменяемые множества:** `frozenset`;
- **диапазоны:** `range`;
- **байтовые строки:** `bytes`;
- **отсутствие значения:** `NoneType`.

```python
items = [1, 2]
same_items = items
items.append(3)       # изменён существующий список

text = "Py"
old_text = text
text += "thon"        # имя text теперь связано с другой строкой
```

`id()` возвращает идентификатор объекта. Он полезен для демонстрации, но строить логику программы на конкретном значении `id()` нельзя.

## Почему изменяемость важна?

Изменяемость влияет на:

- появление побочных эффектов в функциях;
- поверхностное и глубокое копирование;
- значения аргументов по умолчанию;
- возможность использовать объект как ключ `dict` или элемент `set`;
- безопасную передачу и совместное использование данных.

```python
def add_item(items):
    items.append("new")


data = []
add_item(data)
print(data)  # ["new"]
```

Функция изменила тот же список, на который ссылается `data`.

Если исходный объект менять не нужно, можно вернуть новую коллекцию:

```python
def with_item(items):
    return [*items, "new"]
```

## Можно ли изменить список внутри кортежа?

Да. Кортеж изменить нельзя, но внутри него может находиться изменяемый объект, например список.

Кортеж хранит ссылки на объекты. Нельзя заменить ссылку в элементе кортежа, но сам объект по этой ссылке может измениться:

```python
value = (1, ["a"])
value[1].append("b")

print(value)  # (1, ["a", "b"])
```

Сам кортеж остался тем же и по-прежнему содержит тот же список. Изменилось содержимое списка.

Такой кортеж нельзя использовать как ключ словаря, потому что внутри него находится нехешируемый список.

## Что хранит переменная?

**Короткий ответ**

Переменная в Python — это имя, связанное с объектом. Обычное присваивание не копирует объект, а создаёт ещё одну ссылку на него.

```python
first = [1, 2]
second = first
second.append(3)

print(first)  # [1, 2, 3]
```

Оба имени ссылаются на один список.

## Как аргументы передаются в функцию: по ссылке или по значению?

**Короткий ответ**

При вызове функции её параметр начинает ссылаться на тот же объект, который был передан снаружи.

Точная формулировка: **объектная ссылка передаётся по значению**. Эту модель также называют *call by sharing* или передачей по присваиванию.

```python
def mutate(items):
    items.append(3)


values = [1, 2]
mutate(values)
print(values)  # [1, 2, 3]
```

Функция получила ссылку на тот же список и изменила его, поэтому изменение видно снаружи.

Но присваивание нового объекта параметру меняет только локальную переменную функции:

```python
def rebind(items):
    items = [9]


values = [1, 2]
rebind(values)
print(values)  # [1, 2]
```

Поэтому просто ответить «по ссылке» неправильно: функция может изменить переданный объект, но не может своим обычным присваиванием заставить переменную вызывающего кода ссылаться на другой объект.

## В чём проблема изменяемого аргумента по умолчанию?

**Короткий ответ**

Значения аргументов по умолчанию вычисляются один раз — при создании функции. Изменяемый объект будет общим для всех вызовов, в которых аргумент не передан.

```python
# Плохо
def collect(value, result=[]):
    result.append(value)
    return result
```

```python
# Хорошо
def collect(value, result=None):
    if result is None:
        result = []
    result.append(value)
    return result
```

Иногда общее состояние создают намеренно, но тогда это должно быть явно и понятно из кода.
