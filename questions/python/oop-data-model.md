## Какие принципы ООП поддерживает Python?

- **Инкапсуляция** — объединение состояния и поведения, управление публичным интерфейсом.
- **Наследование** — создание класса на основе другого.
- **Полиморфизм** — одинаковый интерфейс для объектов разных типов.
- **Абстракция** — выделение существенного контракта и сокрытие деталей.

Python не обеспечивает строгую приватность полей на уровне языка. Инкапсуляция во многом держится на соглашениях, свойствах и корректном дизайне API.

## Что такое инкапсуляция?

**Короткий ответ**

Инкапсуляция объединяет данные и операции над ними и отделяет публичный контракт объекта от внутренней реализации.

```python
class ApiClient:
    def __init__(self, token):
        self._token = token

    def get_user(self, user_id):
        return self._request("GET", f"/users/{user_id}")

    def _request(self, method, path):
        ...
```

Пользователь клиента вызывает `get_user()` и не обязан знать, как собираются заголовки, выполняются повторы или десериализуется ответ.

В Python:

- публичное имя не начинается с `_`;
- `_name` обозначает внутреннюю деталь по соглашению;
- `__name` включает name mangling, но не создаёт настоящую приватность;
- `property` позволяет сохранить удобный публичный интерфейс при добавлении проверки.

Инкапсуляция — не просто «спрятать поле», а уменьшить число деталей, от которых зависит остальной код.

## Что такое наследование?

Наследование создаёт новый класс на основе существующего и выражает отношение «наследник является разновидностью базового типа».

```python
class BaseClient:
    def request(self, method, path):
        ...


class UserClient(BaseClient):
    def get_user(self, user_id):
        return self.request("GET", f"/users/{user_id}")
```

Наследник получает поведение базового класса и может расширять или переопределять его.

Для AQA наследование встречается в page objects, клиентах и базовых классах тестов. Слишком большой `BaseTest` или `BasePage` часто превращается в связанную иерархию. Если отношение «является» не выполняется, композиция обычно лучше.

## Что такое полиморфизм?

Полиморфизм позволяет одинаково работать с объектами разных типов через общий контракт.

```python
class JsonReporter:
    def publish(self, result):
        ...


class ConsoleReporter:
    def publish(self, result):
        ...


def report(result, reporter):
    reporter.publish(result)
```

`report()` не зависит от конкретной реализации. В Python полиморфизм достигается через:

- наследование и переопределение методов;
- утиную типизацию;
- абстрактные базовые классы;
- `Protocol`;
- специальные методы, например `__iter__`.

Для тестов это позволяет передать реальный клиент, fake или mock с одним интерфейсом.

## Что такое абстракция?

Абстракция выделяет существенный контракт и скрывает несущественные детали.

```python
from abc import ABC, abstractmethod


class Storage(ABC):
    @abstractmethod
    def save(self, result):
        ...
```

Конкретные реализации решают, сохранять ли результат в файл, БД или внешнюю систему. Пользователь зависит от операции `save`, а не от деталей хранения.

Абстракцию можно выразить:

- обычным документированным интерфейсом и duck typing;
- `abc.ABC` и `@abstractmethod` для проверки при создании объекта;
- `typing.Protocol` для структурной статической типизации.

Хорошая абстракция уменьшает связанность. Плохая лишь добавляет слои и повторяет API конкретной реализации.

## Что такое класс, объект, атрибут и метод?

- класс описывает создание и поведение объектов;
- объект — экземпляр класса;
- атрибут — значение, доступное через объект или класс;
- метод — функция, получаемая через атрибут класса и связанная с объектом или классом.

```python
class User:
    category = "person"  # атрибут класса

    def __init__(self, name):
        self.name = name  # атрибут экземпляра

    def greet(self):
        return f"Hello, {self.name}"
```

Атрибут экземпляра ищется сначала в экземпляре, затем в его классе и базовых классах согласно MRO.

## Чем `__new__` отличается от `__init__`?

**Короткий ответ**

`__new__` создаёт и возвращает объект, а `__init__` инициализирует уже созданный объект и должен вернуть `None`.

Порядок:

1. вызывается `Class.__new__(Class, ...)`;
2. если вернулся экземпляр `Class`, вызывается `__init__(self, ...)`;
3. вызывающий код получает объект.

```python
class User:
    def __new__(cls, *args, **kwargs):
        instance = super().__new__(cls)
        return instance

    def __init__(self, name):
        self.name = name
```

`__new__` часто переопределяют у неизменяемых типов, в метаклассах, фабриках и некоторых реализациях singleton. Для обычного класса достаточно `__init__`.

## Что такое магические методы?

Магические, специальные или dunder-методы имеют имена вида `__method__` и подключают объект к синтаксису и протоколам языка.

| Метод | Использование |
|---|---|
| `__init__` | инициализация экземпляра |
| `__repr__`, `__str__` | текстовое представление |
| `__len__` | `len(obj)` |
| `__iter__`, `__next__` | итерация |
| `__getitem__` | `obj[key]` |
| `__enter__`, `__exit__` | `with` |
| `__eq__`, `__lt__` | сравнение |
| `__hash__` | `hash(obj)` |
| `__call__` | `obj()` |

Специальные методы обычно вызывают через соответствующую встроенную операцию: `len(obj)`, а не `obj.__len__()`.

Не стоит придумывать собственные имена с двумя подчёркиваниями с обеих сторон: этот формат зарезервирован для протоколов Python.

## Чем instance method, `classmethod` и `staticmethod` отличаются?

```python
class User:
    def instance_method(self):
        return self

    @classmethod
    def from_string(cls, value):
        return cls(value)

    @staticmethod
    def is_valid_name(value):
        return bool(value.strip())
```

- обычный метод получает экземпляр `self`;
- `classmethod` получает класс `cls` и подходит для альтернативных конструкторов и полиморфной работы с классом;
- `staticmethod` ничего не получает автоматически и является обычной функцией, логически расположенной в пространстве имён класса.

## Что делает `property`?

`property` позволяет обращаться к методу как к атрибуту и управлять чтением, присваиванием и удалением значения.

```python
class Temperature:
    def __init__(self, celsius):
        self.celsius = celsius

    @property
    def celsius(self):
        return self._celsius

    @celsius.setter
    def celsius(self, value):
        if value < -273.15:
            raise ValueError("Below absolute zero")
        self._celsius = value
```

Свойство полезно для валидации и вычисляемых атрибутов. Тяжёлый ввод-вывод за обычным свойством лучше не скрывать: чтение атрибута ожидается дешёвым.

## Что означают одинарное и двойное подчёркивания?

- `_name` — внутренний атрибут по соглашению; доступ не запрещён;
- `name_` — избегание конфликта с ключевым словом;
- `__name` — name mangling: внутри `Class` превращается примерно в `_Class__name`;
- `__name__` — специальное имя протокола Python.

Name mangling помогает избежать случайного конфликта имён в наследниках, но не обеспечивает безопасность:

```python
class Example:
    def __init__(self):
        self.__value = 10


obj = Example()
obj._Example__value  # технически доступно
```

## Как обратиться к родительскому классу?

Обычно через `super()`:

```python
class Admin(User):
    def __init__(self, name, permissions):
        super().__init__(name)
        self.permissions = permissions
```

`super()` означает не просто «мой непосредственный родитель», а «следующий класс в MRO». Это особенно важно при множественном наследовании.

Для кооперативного множественного наследования совместимые методы должны вызывать `super()` и иметь согласованные сигнатуры.

## Что такое MRO?

**MRO** (*Method Resolution Order*) — порядок, в котором Python ищет атрибуты в классе и его базовых классах.

```python
print(MyClass.__mro__)
print(MyClass.mro())
```

Python 3 использует алгоритм C3 linearization. Он:

- сохраняет порядок перечисления базовых классов;
- не ставит базовый класс раньше его наследника;
- строит согласованный порядок либо отклоняет иерархию.

### Что такое «MRO2 и MRO3»?

Это не общепринятые названия алгоритмов. Обычно вопрос относится к Python 2 и Python 3:

- old-style классы Python 2 использовали простой поиск в глубину;
- new-style классы Python 2 и все классы Python 3 используют C3 MRO.

## Что такое diamond problem и миксины?

«Ромб» возникает, когда класс наследуется от двух классов с общей базой:

```text
    Base
   /    \
 Left  Right
   \    /
   Child
```

C3 MRO задаёт однозначный порядок и при корректном `super()` позволяет вызвать каждый совместимый метод один раз.

**Миксин** — небольшой класс, добавляющий одну возможность и не предназначенный для самостоятельного создания объектов.

```python
class JsonMixin:
    def to_json(self):
        ...
```

Миксины стоит делать узкими, без сложного собственного состояния и неочевидных требований к наследнику.

## Чем композиция отличается от наследования?

**Наследование** выражает отношение «является» (*is-a*), а **композиция** — «содержит или использует» (*has-a*).

```python
class ApiClient:
    def get(self, path):
        ...


class UserService:
    def __init__(self, client: ApiClient):
        self.client = client

    def get_user(self, user_id):
        return self.client.get(f"/users/{user_id}")
```

`UserService` не является разновидностью `ApiClient`, а использует его. Это композиция.

Для тестовой автоматизации композиция обычно удобна:

- зависимости можно передавать через конструктор;
- реальный клиент легко заменить стабом или mock;
- классы меньше связаны между собой;
- изменение одной реализации реже ломает иерархию.

Наследование уместно, когда действительно существует общий контракт и наследник должен везде корректно заменять базовый тип. Правило «предпочитай композицию наследованию» не запрещает наследование, а требует не использовать его только ради повторного использования кода.

## Что такое `__slots__`?

`__slots__` объявляет допустимые атрибуты экземпляра и обычно убирает автоматический `__dict__`.

```python
class Point:
    __slots__ = ("x", "y")

    def __init__(self, x, y):
        self.x = x
        self.y = y
```

Плюсы:

- может заметно уменьшить память для большого числа экземпляров;
- предотвращает случайное добавление других атрибутов;
- иногда ускоряет доступ к атрибутам.

Минусы и нюансы:

- усложняет наследование;
- без `__dict__` нельзя добавлять произвольные поля;
- для weak references нужно добавить `__weakref__`;
- это оптимизация и ограничение структуры, а не механизм приватности.

## Что такое утиная типизация?

«Если объект ведёт себя как утка, используем его как утку»: важен поддерживаемый интерфейс, а не конкретный класс.

```python
def write_report(stream):
    stream.write("report")
```

Функции подойдёт файл, `io.StringIO` или любой объект с подходящим `write()`.

Статический вариант утиной типизации можно выразить через `typing.Protocol`.

## Что такое dataclass и namedtuple?

Оба инструмента удобны для небольших записей с именованными полями.

```python
from dataclasses import dataclass


@dataclass(frozen=True)
class Point:
    x: int
    y: int
```

```python
from collections import namedtuple

Point = namedtuple("Point", ["x", "y"])
```

| `dataclass` | `namedtuple` |
|---|---|
| обычный класс | подкласс `tuple` |
| по умолчанию изменяем | неизменяем |
| удобно добавлять методы и валидацию | поддерживает индексы и распаковку как tuple |
| гибко настраивает `eq`, `order`, `frozen`, `slots` | компактен и совместим с tuple API |

В современном прикладном коде `dataclass` обычно гибче. `NamedTuple` остаётся полезным для компактной неизменяемой записи, совместимой с кортежем.

## Что такое метакласс?

**Короткий ответ**

Метакласс — класс, экземплярами которого являются классы. Метакласс по умолчанию — `type`.

```python
class User:
    pass


isinstance(User, type)  # True
```

Метакласс может проверять или изменять создаваемый класс:

```python
class RegistryMeta(type):
    registry = {}

    def __new__(mcls, name, bases, namespace):
        cls = super().__new__(mcls, name, bases, namespace)
        mcls.registry[name] = cls
        return cls
```

Python выбирает явно указанный `metaclass=` либо наиболее производный совместимый метакласс базовых классов. Несовместимые метаклассы вызывают `TypeError`.

Метаклассы нужны редко. Часто проще использовать декоратор класса, `__init_subclass__` или обычную фабрику.

## Что такое интроспекция и рефлексия?

**Интроспекция** — получение информации об объекте во время выполнения:

```python
type(obj)
isinstance(obj, User)
dir(obj)
getattr(obj, "name")
hasattr(obj, "save")
```

Модуль `inspect` позволяет изучать сигнатуры, классы, функции и исходный код.

**Рефлексия** — более широкое понятие: изучение и изменение программы через её представление во время выполнения. В Python к ней относят `getattr`, `setattr`, дескрипторы, декораторы классов и метаклассы.

## Существуют ли old-style classes в Python 3?

Нет. В Python 3 все классы являются new-style и неявно наследуют `object`.

```python
class User:
    pass


issubclass(User, object)  # True
```

Различие имеет только историческое значение для Python 2.
