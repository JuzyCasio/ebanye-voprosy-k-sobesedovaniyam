## Чем конкурентность отличается от параллелизма?

- **Конкурентность** — программа занимается несколькими задачами за один промежуток времени, переключаясь между ними во время ожидания.
- **Параллелизм** — несколько задач действительно выполняются одновременно, например на разных ядрах процессора.

Один поток с `asyncio` может конкурентно обслуживать множество сетевых операций, переключаясь во время ожидания. Несколько процессов могут выполнять CPU-задачи параллельно на разных ядрах.

## Что такое поток и процесс?

**Процесс** — отдельный запущенный экземпляр программы со своей памятью. **Поток** — отдельная линия выполнения внутри процесса. Потоки одного процесса используют общую память.

| Процесс | Поток |
|---|---|
| отдельное адресное пространство | разделяет память процесса |
| тяжелее создавать и переключать | обычно легче |
| данные нужно сериализовать или помещать в shared memory | объекты доступны всем потокам процесса |
| сбой сильнее изолирован | ошибка может повредить общее состояние |
| подходит для CPU-bound параллелизма | часто подходит для блокирующего I/O |

Потоки одного процесса разделяют глобальные переменные и объекты, поэтому нуждаются в синхронизации. Процессы изолированы, но обмен между ними сложнее.

## Что такое GIL?

**Короткий ответ**

GIL — это блокировка внутри обычной сборки CPython. Из-за неё в один момент времени Python-код выполняет только один поток одного интерпретатора.

Поэтому потоки хорошо помогают при ожидании сети или файлов, но обычно не ускоряют вычисления на чистом Python.

Следствия:

- потоки не дают обычному Python-коду линейного ускорения CPU-bound вычислений;
- потоки полезны для I/O-bound работы, потому что во время многих операций ввода-вывода GIL освобождается;
- C-расширения также могут освобождать GIL на тяжёлых вычислениях;
- GIL не устраняет race conditions и не делает составные операции автоматически потокобезопасными.

### У GIL есть исключения?

Начиная с Python 3.13 существуют официальные **free-threaded** сборки CPython, где GIL можно отключить. Они пока являются отдельным вариантом запуска, а сторонние расширения могут включать GIL обратно. На собеседовании важно уточнять: речь об обычной сборке CPython или о free-threaded.

## Являются ли потоки Python настоящими потоками ОС?

Да. `threading.Thread` в CPython работает поверх нативных потоков операционной системы. GIL ограничивает одновременное выполнение Python-байткода, но не превращает потоки в «ненастоящие».

Не следует путать их с:

- задачами `asyncio`, которые планируются event loop;
- green threads/greenlets, которые планирует библиотека в пользовательском пространстве;
- процессами `multiprocessing`.
