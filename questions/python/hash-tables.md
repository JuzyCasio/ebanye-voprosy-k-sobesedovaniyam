# Хеш-таблицы: словари и множества

[← К разделу Python](../python.md)

## Что такое словарь?

**Короткий ответ**

Словарь (`dict`) хранит пары «ключ — значение». По ключу можно быстро получить, добавить или изменить соответствующее значение.

Ключи в словаре уникальны и должны быть хешируемыми.

```python
user = {
    "id": 42,
    "name": "Alex",
}

print(user["name"])  # Alex
```

Значения словаря могут иметь любые типы и не обязаны быть уникальными.

## Является ли `dict` хеш-таблицей?

**Короткий ответ**

Да. В Python словарь устроен как хеш-таблица. Python вычисляет хеш ключа и с его помощью быстро находит нужную запись.

`set` тоже основан на хеш-таблице, но хранит только уникальные элементы без отдельных значений.

Для обычного ответа на собеседовании фразы «`dict` — словарь на основе хеш-таблицы» достаточно. Точное расположение данных в памяти является внутренней деталью конкретной реализации Python.

## Как словарь находит значение?

Если сильно упростить, поиск работает так:

1. Python вычисляет `hash(key)`.
2. По хешу определяет начальную позицию в таблице.
3. Если позиция занята, Python проверяет найденный ключ.
4. Сначала сравнивается хеш, затем при необходимости ключи через `==`.
5. Если ключи равны, возвращается соответствующее значение.
6. При коллизии проверяются другие позиции по внутреннему алгоритму.

```python
users = {42: "Alex"}
name = users[42]
```

Python не перебирает все ключи с начала при каждом нормальном поиске. Поэтому средняя сложность доступа по ключу — `O(1)`.

## Почему поиск в словаре быстрее поиска в списке?

**Короткий ответ**

В списке Python обычно проверяет элементы по очереди, поэтому поиск занимает `O(n)`. Словарь и множество используют хеш и в среднем находят элемент за `O(1)`, то есть время поиска обычно не растёт линейно вместе с количеством элементов.

| Структура и операция | Средняя сложность |
|---|---:|
| `value in list` | `O(n)` |
| `key in dict` | `O(1)` |
| `value in set` | `O(1)` |
| поиск в отсортированной последовательности бинарным поиском | `O(log n)` |

```python
allowed_list = ["admin", "editor", "viewer"]
allowed_set = {"admin", "editor", "viewer"}

"editor" in allowed_list  # последовательный поиск
"editor" in allowed_set   # поиск по хеш-таблице
```

Словарь не «быстрее списка вообще». Например, список лучше подходит для компактной упорядоченной последовательности и доступа по целочисленному индексу. Хеш-таблица также расходует дополнительную память.

## Что такое коллизия?

**Короткий ответ**

Коллизия — ситуация, когда разные ключи получили одинаковый хеш или попали в одно место таблицы. Это не ошибка: словарь умеет обработать такую ситуацию и дополнительно сравнивает ключи.

Одинаковый хеш не означает равенство объектов:

```python
hash(first) == hash(second)  # возможно
first == second              # не обязательно True
```

Но для корректно реализованных объектов действует обратное требование:

```python
first == second  # если True,
hash(first) == hash(second)  # хеши обязаны совпадать
```

Большое число неудачных коллизий ухудшает производительность. В худшем случае операция хеш-таблицы может приблизиться к `O(n)`, поэтому `O(1)` называют средней, а не гарантированной сложностью.

## Что такое хешируемый объект?

**Короткий ответ**

Хешируемый объект — это объект, для которого можно вызвать `hash()` и чей хеш не меняется во время его жизни. Такой объект можно использовать как ключ словаря или элемент множества.

Если два объекта равны через `==`, их хеши также должны быть равны.

```python
hash(42)          # int хешируем
hash("user_id")   # str хешируем
hash((1, 2))      # такой tuple хешируем
hash([1, 2])      # TypeError: list не хешируем
```

### Все ли неизменяемые объекты хешируемы?

Нет. Неизменяемость и хешируемость связаны, но это разные свойства. Например, кортеж хешируем только тогда, когда хешируемы все его элементы:

```python
hash((1, "a"))      # допустимо
hash((1, ["a"]))    # TypeError
```

### Все ли изменяемые объекты нехешируемы?

Большинство изменяемых встроенных коллекций нехешируемы. Но пользовательский класс по умолчанию может хешироваться по идентичности, даже если его атрибуты изменяются. При реализации собственного `__eq__` и `__hash__` важно не нарушить правило стабильности хеша.

На обычном собеседовании достаточно сформулировать безопасное практическое правило: ключ словаря не должен изменяться так, чтобы менялись его равенство или хеш.

## Почему список нельзя использовать как ключ?

Список можно изменить после создания, поэтому он не имеет постоянного хеша. Если бы изменившийся список использовался как ключ, словарь мог бы перестать находить связанную с ним запись.

```python
mapping = {
    [1, 2]: "value"  # TypeError: unhashable type: 'list'
}
```

Вместо списка для составного ключа обычно используют кортеж из хешируемых элементов:

```python
coordinates = {
    (55.75, 37.62): "Moscow",
}
```

## Какие нюансы есть у числовых ключей?

Числовые значения разных типов могут считаться равными и иметь одинаковый хеш:

```python
1 == 1.0 == True
hash(1) == hash(1.0) == hash(True)
```

Поэтому для словаря это один логический ключ:

```python
data = {
    1: "int",
    1.0: "float",
    True: "bool",
}

len(data)   # 1
data[1]     # "bool"
```

Каждое следующее присваивание заменило значение существующего ключа. В тестовых данных не стоит смешивать такие ключи, если различие типов имеет смысл.

Также нужно помнить о специальных значениях `float`, например `NaN`: они имеют необычную семантику равенства. Для устойчивых идентификаторов лучше использовать строки, целые числа, UUID или предметные неизменяемые типы.

## Чем словарь отличается от множества?

| `dict` | `set` |
|---|---|
| хранит пары «ключ — значение» | хранит уникальные элементы |
| доступ к значению выполняется по ключу | основная операция — проверка принадлежности |
| литерал `{"id": 10}` | литерал `{10, 20}` |
| пустой словарь `{}` | пустое множество `set()` |
| сохраняет порядок добавления | порядок не гарантирован |

Словарь хранит пары «ключ — значение», а множество — только уникальные элементы.

Обе структуры используют хеш-таблицу. Ключи словаря и элементы множества должны быть хешируемыми.

## Чем список отличается от множества?

**Короткий ответ**

Список сохраняет порядок, допускает дубликаты и поддерживает индексы. Множество хранит уникальные хешируемые элементы, не поддерживает индексы и в среднем быстрее проверяет принадлежность.

```python
items = [3, 1, 3]   # порядок и повтор сохранены
unique = {3, 1, 3}  # осталось два элемента
```

`set` не подходит, если:

- нужен стабильный порядок элементов;
- требуются дубликаты;
- нужен доступ по индексу;
- элементы нехешируемы, например списки или словари.

## Как множества сравниваются на равенство?

Два множества равны, если содержат одинаковые элементы. Порядок не участвует:

```python
{1, 2, 3} == {3, 2, 1}  # True
```

Операторы `<`, `<=`, `>`, `>=` у множеств проверяют строгое и нестрогое отношение подмножества/надмножества, а не лексикографический порядок:

```python
{1, 2} < {1, 2, 3}  # True
```

Множества могут быть несравнимы по включению: тогда оба выражения `left < right` и `right < left` будут ложными.

## Сохраняет ли словарь порядок?

Да. Начиная с Python 3.7 порядок добавления ключей является гарантией языка.

```python
data = {}
data["b"] = 1
data["a"] = 2

list(data)  # ["b", "a"]
```

Это **порядок добавления**, а не автоматическая сортировка по ключам. Обновление значения существующего ключа обычно не перемещает его в конец. Удаление ключа и последующее добавление создаёт новую позицию в порядке.

Для `set` порядок не гарантирован, даже если в конкретном запуске он выглядит стабильным.

## Как работать со словарями?

### Получение значений

```python
user = {"name": "Alex"}

user["name"]        # "Alex"; KeyError, если ключа нет
user.get("age")     # None, если ключа нет
user.get("age", 0)  # 0, если ключа нет
```

`get()` используют, когда отсутствие ключа ожидаемо. Квадратные скобки полезны, когда ключ обязан существовать и его отсутствие означает ошибку.

Нельзя отличить отсутствующий ключ от ключа со значением `None` одним вызовом `get()` без специального маркера:

```python
missing = object()
value = user.get("age", missing)

if value is missing:
    print("Ключ отсутствует")
```

### Добавление и обновление

```python
user["age"] = 30
user.update({"name": "Alexander", "active": True})
```

Если присвоить значение существующему ключу, прежнее значение будет заменено.

### Перебор

```python
for key in user:
    ...

for value in user.values():
    ...

for key, value in user.items():
    ...
```

Обычная итерация по словарю перебирает ключи.

### Объединение

```python
defaults = {"timeout": 5, "retries": 2}
custom = {"timeout": 10}

settings = defaults | custom
# {"timeout": 10, "retries": 2}
```

При совпадении ключей значение правого словаря получает приоритет.

## Что возвращают `keys`, `values` и `items`?

- `dict.keys()` — представление ключей;
- `dict.values()` — представление значений;
- `dict.items()` — представление пар `(key, value)`.

Методы `keys()`, `values()` и `items()` возвращают представления данных словаря, а не отдельные готовые списки. Если словарь изменится, представление тоже покажет изменения:

```python
data = {"a": 1}
items = data.items()

data["b"] = 2
list(items)  # [("a", 1), ("b", 2)]
```

`items()` удобно использовать для распаковки:

```python
for key, value in data.items():
    ...
```

## Как составить словарь из списков ключей и значений?

```python
keys = ["name", "age"]
values = ["Alex", 30]

user = dict(zip(keys, values, strict=True))
```

Без `strict=True` обычный `zip` остановится на более коротком iterable, и лишние элементы потеряются молча. `strict=True` вызывает `ValueError`, если длины различаются, что часто безопаснее в тестовом коде.

Если ключ повторяется, более поздняя пара перезаписывает предыдущее значение.

## Какие операции есть у множеств?

```python
left = {1, 2, 3}
right = {3, 4}

left | right   # объединение: {1, 2, 3, 4}
left & right   # пересечение: {3}
left - right   # разность: {1, 2}
left ^ right   # симметрическая разность: {1, 2, 4}
left <= right  # является ли left подмножеством right
left >= right  # является ли left надмножеством right
```

Методы `add`, `remove`, `discard`, `pop` и `clear` изменяют множество:

```python
values = {1, 2}
values.add(3)
values.discard(10)  # ошибки нет
values.remove(10)   # KeyError
```

`frozenset` является неизменяемой версией множества. Его можно использовать как ключ словаря или элемент другого множества.

## Как удалить дубликаты?

Если элементы хешируемы и порядок нужно сохранить:

```python
values = [3, 1, 3, 2, 1]
unique = list(dict.fromkeys(values))

print(unique)  # [3, 1, 2]
```

Если порядок не важен:

```python
unique = list(set(values))
```

Для нехешируемых элементов, например списков или словарей, нужен другой критерий уникальности или явный проход.

## Какова сложность операций?

| Операция | `list` | `dict` | `set` |
|---|---:|---:|---:|
| доступ по индексу | `O(1)` | — | — |
| поиск значения | `O(n)` | значения: `O(n)` | в среднем `O(1)` |
| поиск ключа | — | в среднем `O(1)` | — |
| добавление в конец | амортизированно `O(1)` | — | — |
| вставка/удаление в начале или середине | `O(n)` | — | — |
| добавление/удаление ключа или элемента | — | в среднем `O(1)` | в среднем `O(1)` |
| перебор всех элементов | `O(n)` | `O(n)` | `O(n)` |

### Частая ловушка

Проверка `value in mapping` ищет значение среди **ключей**, а не среди значений:

```python
mapping = {"name": "Alex"}

"name" in mapping           # True, среднее O(1)
"Alex" in mapping           # False
"Alex" in mapping.values()  # True, но поиск O(n)
```
