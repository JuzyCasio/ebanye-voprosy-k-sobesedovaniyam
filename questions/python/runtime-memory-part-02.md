## Что такое сборка мусора?

В CPython у объекта есть счётчик ссылок. Когда на объект больше никто не ссылается, его обычно можно сразу удалить из памяти.

Отдельный сборщик мусора нужен в основном для циклических ссылок — ситуаций, когда объекты ссылаются друг на друга, но остальная программа уже не может до них добраться.

```python
value = SomeObject()
other = value

del value  # одна ссылка остаётся
del other  # объект может быть освобождён
```

Подсчёт ссылок не справляется с циклами:

```python
first.ref = second
second.ref = first
```

Для обнаружения недостижимых циклов CPython использует циклический garbage collector из модуля `gc`.

Практические выводы:

- не следует рассчитывать на момент вызова `__del__`;
- внешние ресурсы нужно закрывать через `with`, а не ждать GC;
- циклы с финализаторами и большие графы объектов могут усложнять освобождение памяти;
- утечка может быть не только «неосвобождённой памятью», но и ненужной живой ссылкой в кеше или глобальной коллекции.

## Что такое интернирование?

Интернирование — это переиспользование одного объекта для одинаковых неизменяемых значений. Интерпретатор может так делать с некоторыми строками и числами, чтобы экономить память.

```python
first = "python"
second = "python"

first is second  # может быть True, но это не контракт для сравнения значений
```

Интернирование — причина, по которой ошибочный код с `is` иногда случайно работает. Значения сравнивают через `==`.

## Как проверить тип объекта?

`type()` возвращает точный тип объекта. `isinstance()` проверяет, относится ли объект к указанному классу или его наследникам.

```python
type(value) is int
isinstance(value, int)
```

- `type(value) is SomeType` требует точного типа;
- `isinstance(value, SomeType)` учитывает наследование;
- `isinstance(value, (int, float))` проверяет несколько типов.

В полиморфном коде обычно предпочтительнее `isinstance` или проверка требуемого поведения. Для тестов точная проверка `type(...) is ...` уместна, если подкласс действительно недопустим.

## Как проверить изменяемость объекта?

Универсальной функции, которая точно определяет изменяемость любого объекта, в Python нет.

Практически используют:

- знание контракта конкретного типа;
- проверку документации;
- наличие операций изменения — только как подсказку;
- попытку изменить объект в контролируемом тесте.

Хешируемость не является точным тестом изменяемости. Большинство изменяемых встроенных контейнеров нехешируемы, но пользовательский изменяемый объект может иметь хеш по идентичности.
