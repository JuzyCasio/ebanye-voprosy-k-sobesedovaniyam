## Какие коллекции из `collections` важно знать?

Модуль `collections` содержит специализированные коллекции. На собеседовании чаще всего спрашивают:

| Инструмент | Назначение |
|---|---|
| `deque` | быстрая работа с обоими концами очереди |
| `Counter` | подсчёт хешируемых элементов |
| `defaultdict` | автоматическое значение для отсутствующего ключа |
| `namedtuple` | неизменяемая tuple-запись с именованными полями |
| `ChainMap` | единое представление нескольких отображений |

`OrderedDict` всё ещё имеет специальные операции и другое поведение равенства, но для простого сохранения порядка обычного `dict` достаточно.

## Чем `deque` отличается от `list`?

`deque` — двусторонняя очередь. Она быстро добавляет и удаляет элементы как справа, так и слева.

```python
from collections import deque

queue = deque([1, 2])
queue.append(3)
first = queue.popleft()
```

| Операция | `list` | `deque` |
|---|---:|---:|
| `append`, `pop` справа | `O(1)` амортизированно | `O(1)` |
| вставка/удаление слева | `O(n)` | `O(1)` |
| доступ по индексу в середине | `O(1)` | `O(n)` |

Для очереди обычно выбирают `deque`, для произвольного доступа по индексам — `list`.

## Как работают `Counter` и `defaultdict`?

`Counter` считает, сколько раз встретился каждый элемент. `defaultdict` автоматически создаёт значение для отсутствующего ключа.

```python
from collections import Counter

statuses = Counter(["passed", "failed", "passed"])
statuses["passed"]  # 2
statuses.most_common(1)
```

```python
from collections import defaultdict

tests_by_suite = defaultdict(list)
tests_by_suite["api"].append("test_users")
```

`defaultdict(factory)` вызывает фабрику только при обращении к отсутствующему ключу через `[]`. Метод `get()` фабрику не вызывает.

Обычный `dict.setdefault()` также может создать значение:

```python
tests_by_suite.setdefault("api", []).append("test_users")
```

Но выражение значения для `setdefault` вычисляется при каждом вызове, даже если ключ уже есть.

## Для чего нужны `functools`, `itertools` и `operator`?

- `functools` содержит инструменты для работы с функциями;
- `itertools` помогает создавать и объединять ленивые итераторы;
- `operator` предоставляет обычные операции в виде функций.

### `functools`

- `wraps` — метаданные декорируемой функции;
- `partial` — частичное применение аргументов;
- `reduce` — свёртка последовательности;
- `cache`, `lru_cache` — кеширование;
- `singledispatch` — диспетчеризация по типу.

### `itertools`

Ленивые инструменты для итераций:

- `chain`;
- `islice`;
- `product`;
- `permutations`, `combinations`;
- `groupby`;
- `repeat`, `cycle`, `count`.

В AQA `product()` удобен для генерации комбинаций параметров, но неконтролируемое декартово произведение быстро раздувает число тестов.

### `operator`

Предоставляет операции в виде функций:

```python
from operator import attrgetter, itemgetter

sorted(users, key=itemgetter("name"))
sorted(objects, key=attrgetter("created_at"))
```

## Что такое `lru_cache`?

`lru_cache` запоминает результат функции для уже встречавшегося набора аргументов. При повторном вызове функция не выполняется заново, а возвращает результат из кеша.

```python
from functools import lru_cache


@lru_cache(maxsize=128)
def load_schema(name):
    ...
```

Аргументы должны быть хешируемыми. Кеш подходит для детерминированных функций без нежелательных побочных эффектов.

Риски в тестах:

- состояние кеша протекает между тестами;
- результат устаревает;
- кеш удерживает ссылки на аргументы и результаты.

Для изоляции можно вызвать `load_schema.cache_clear()` в фикстуре.

## Чем `Decimal` отличается от `float`?

`float` хранит числа в двоичном формате, поэтому некоторые десятичные дроби представлены неточно:

```python
0.1 + 0.2 == 0.3  # False
```

`Decimal` хранит десятичные числа с управляемой точностью:

```python
from decimal import Decimal

Decimal("0.1") + Decimal("0.2") == Decimal("0.3")  # True
```

`Decimal` создают из строки, если нужна точная десятичная величина. Он медленнее и не должен бездумно смешиваться с `float`.

В тестах `float` обычно сравнивают с допуском, например `pytest.approx`, а денежные значения — согласно контракту системы, часто через `Decimal`.

## Как работать с timezone?

Объект `datetime` может быть:

- **naive** — без информации о часовом поясе;
- **aware** — с часовым поясом.

Для API и автотестов обычно безопаснее хранить и сравнивать время в UTC, а локальный часовой пояс применять только при отображении.

- **naive** — без информации о часовом поясе;
- **aware** — с `tzinfo`.

```python
from datetime import UTC, datetime

now = datetime.now(UTC)
```

Для часовых поясов IANA:

```python
from zoneinfo import ZoneInfo

moscow = ZoneInfo("Europe/Moscow")
local_time = now.astimezone(moscow)
```

Практика для автотестов:

- хранить и передавать время в UTC, если контракт не требует иного;
- явно проверять формат и offset;
- не сравнивать локальное «текущее время» на точное равенство;
- учитывать переходы DST для соответствующих зон;
- замораживать часы или внедрять источник времени в детерминированных тестах.

## Как скопировать словарь?

Есть поверхностная и глубокая копия. Поверхностная создаёт новый словарь, но вложенные изменяемые объекты остаются общими.

Поверхностные копии:

```python
copy_1 = original.copy()
copy_2 = dict(original)
copy_3 = {**original}
copy_4 = original | {}
```

Вложенные изменяемые объекты остаются общими. Для независимого копирования всего графа применяют `copy.deepcopy()`, если такая семантика действительно нужна.

## Какие инструменты качества кода полезны AQA?

- `ruff` — быстрый линтер и форматирование;
- `black` — форматирование;
- `mypy` или `pyright` — статическая проверка типов;
- `pytest` — тестовый фреймворк;
- `coverage.py` / `pytest-cov` — покрытие;
- `pre-commit` — автоматический запуск проверок перед коммитом;
- `pip-audit` — поиск известных уязвимостей зависимостей.

Конкретный набор определяется проектом. Важнее, чтобы проверки одинаково запускались локально и в CI.
