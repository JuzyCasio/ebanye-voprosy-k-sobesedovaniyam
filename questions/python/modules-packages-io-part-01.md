## Что такое модуль и пакет?

**Модуль** — отдельный файл с Python-кодом, который можно импортировать в другие файлы.

**Пакет** — каталог, который объединяет несколько модулей и подпакетов.

Обычный пакет содержит `__init__.py`. Существуют также namespace packages без этого файла, но для базового ответа на собеседовании достаточно сначала объяснить обычный пакет.

```text
project/
└── api_client/
    ├── __init__.py
    ├── client.py
    └── models.py
```

## Как Python импортирует модуль?

При первом импорте Python находит модуль, создаёт его объект и выполняет код модуля сверху вниз. Повторный импорт обычно использует уже загруженный модуль из `sys.modules`.

Упрощённо:

1. проверяет кеш `sys.modules`;
2. ищет модуль через import finders, обычно используя `sys.path`;
3. создаёт объект модуля;
4. добавляет его в `sys.modules`;
5. выполняет код модуля;
6. связывает нужное имя в текущей области.

Модуль обычно выполняется один раз за процесс, а повторные импорты используют кеш. `importlib.reload()` может выполнить его снова, но не обновляет автоматически все ранее импортированные ссылки.

## Чем разные формы `import` отличаются?

`import module` добавляет в текущий файл имя модуля. `from module import name` добавляет только выбранное имя. `import *` импортирует сразу много имён и обычно не рекомендуется, потому что непонятно, откуда они появились.

```python
import package.module
package.module.function()
```

В текущую область добавляется имя `package`.

```python
from package.module import function
function()
```

Добавляется непосредственная ссылка `function`.

```python
import package.module as module
```

`as` задаёт локальный псевдоним, помогает избежать конфликта или сократить длинное имя.

```python
from package.module import *
```

Wildcard-import затрудняет понимание происхождения имён и может перезаписать существующие. В рабочем коде его обычно избегают. Экспорт частично управляется через `__all__`.

## Когда выполняется `__init__.py`?

`__init__.py` выполняется при первом импорте обычного пакета в текущем процессе.

```python
import package.submodule
```

Сначала инициализируется `package`, затем загружается `package.submodule`.

`__init__.py` может:

- определять публичный API пакета;
- импортировать удобные имена;
- задавать `__all__`;
- выполнять инициализацию.

Тяжёлые сетевые запросы и другие заметные побочные эффекты при импорте обычно являются плохой идеей.

## Почему возникают циклические импорты?

Циклический импорт возникает, когда модуль `a` импортирует `b`, а модуль `b` в ответ импортирует `a`.

Модуль помещается в `sys.modules` до завершения выполнения, поэтому второй импорт может увидеть частично инициализированный объект без нужного атрибута.

Решения:

- вынести общую часть в третий модуль;
- зависеть от более низкого уровня абстракции;
- передавать зависимость параметром;
- иногда перенести импорт внутрь функции как локальный обходной путь.

Циклический импорт часто сигнализирует о слишком сильной связанности модулей.

## Что такое `__name__` и `__main__`?

При импорте `__name__` содержит полное имя модуля. У файла, запущенного как программа, `__name__ == "__main__"`.

```python
def main():
    ...


if __name__ == "__main__":
    main()
```

Так код запуска не выполняется при импорте файла в тесты или другой модуль.
