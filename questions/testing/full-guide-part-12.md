## 48. Root Cause Analysis

Анализ первопричины дефекта.  

Вопросы:  

почему баг возник?  
почему его не нашли раньше?  
почему автотесты не поймали?  
почему требования это не описали?  
как предотвратить повторение?  

### Пример:

Баг был не просто в коде. Первопричина — в требованиях не были описаны права доступа для роли manager.

## 50. Как тестировать пароль

Допустим требования:  

минимум 8 символов;  
хотя бы одна цифра;  
хотя бы одна заглавная буква.  

Тестовые данные:  

Пароль	Ожидаемый результат	Причина  
Password1	True	валидный  
Pass1	False	меньше 8  
password1	False	нет заглавной  
Password	False	нет цифры  
password	False	нет цифры и заглавной  
PASSWORD1	True	есть заглавные и цифра  
Pass word1	зависит от требований	пробел  
Пароль123	зависит от требований	кириллица  
Password123456789	True	длинный валидный  
пустая строка	False	пустой пароль  
None	ошибка или False	зависит от контракта  

### Важно на интервью:

Я бы уточнил требования по спецсимволам, пробелам, кириллице, максимальной длине и поведению при None.

## 53. Как тестировать права доступа

### Подход:

Определить роли.  
Определить доступные действия.  
Составить матрицу прав.  
Проверить UI.  
Проверить API напрямую.  
Проверить БД/логи, если нужно.  

### Пример матрицы:

Действие	Admin	Manager	User	Guest  
Просмотр пользователей	Да	Да	Нет	Нет  
Создание пользователя	Да	Нет	Нет	Нет  
Удаление пользователя	Да	Нет	Нет	Нет  
Просмотр своего профиля	Да	Да	Да	Нет  

### Важно:

Недостаточно скрыть кнопку в UI. Нужно проверить, что API тоже запрещает действие.
