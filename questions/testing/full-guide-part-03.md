## 6. Виды тестирования

Функциональное тестирование  

Проверяет, что система делает то, что должна.  

### Примеры:

логин работает;  
заказ создаётся;  
пароль меняется;  
фильтр ищет нужные данные;  
API возвращает корректный ответ.  
Нефункциональное тестирование  

Проверяет характеристики системы.  

### Примеры:

производительность;  
безопасность;  
удобство использования;  
отказоустойчивость;  
совместимость;  
масштабируемость;  
доступность.  
Smoke Testing  

Быстрая проверка, что сборка вообще пригодна для дальнейшего тестирования.  

### Пример smoke-набора:

приложение открывается;  
пользователь может залогиниться;  
главная страница загружается;  
основной API отвечает;  
критичный сценарий проходит.  

### Короткий ответ:

Smoke — это минимальная проверка жизнеспособности билда.  

Sanity Testing  

Узкая проверка конкретного изменения или исправления.  

### Пример:

Исправили баг в смене пароля. Sanity — проверить именно смену пароля и ближайшие связанные сценарии.  

Разница:  

Smoke — широкий и поверхностный.  
Sanity — узкий и точечный.  
Regression Testing  

### Проверка, что новые изменения не сломали старый функционал.

Регрессия бывает:  

полная;  
частичная;  
автоматизированная;  
ручная;  
риск-ориентированная.  

### Короткий ответ:

Регрессия нужна, чтобы убедиться, что после изменений старый функционал продолжает работать корректно.  

Retesting  

Повторная проверка конкретного исправленного бага.  

Разница:  

Retest — проверить, исправлен ли конкретный баг.  
Regression — проверить, не сломалось ли что-то рядом или в системе в целом.  
Exploratory Testing  

Исследовательское тестирование без заранее детально прописанных тест-кейсов.  

Тестировщик одновременно:  

изучает продукт;  
проектирует тесты;  
выполняет проверки;  
анализирует результат.  

### Хорошо подходит:

когда требования неполные;  
когда мало времени;  
для поиска нестандартных багов;  
для новых фич.  
Ad-hoc Testing  

Свободное тестирование без плана и структуры.  

Похоже на exploratory, но менее формализовано.  

Positive Testing  

### Проверка корректных сценариев.

### Пример:

ввести валидный логин и пароль;  
получить успешный вход.  
Negative Testing  

### Проверка некорректных сценариев.

### Пример:

пустой пароль;  
неправильный email;  
SQL-инъекция в поле;  
слишком длинное значение;  
неверный формат файла.  
Compatibility Testing  

### Проверка совместимости.

### Примеры:

браузеры;  
ОС;  
версии мобильных устройств;  
разрешения экрана;  
версии API;  
версии БД.  
Usability Testing  

### Проверка удобства использования.

### Примеры:

понятные ли ошибки;  
удобно ли заполнить форму;  
видно ли важные кнопки;  
логичен ли пользовательский путь.  
Localization Testing  

### Проверка локализации.

### Что проверять:

переводы;  
форматы дат;  
валюты;  
часовые пояса;  
переносы строк;  
длину текста;  
кириллицу;  
сортировку;  
plural forms.  
Accessibility Testing  

### Проверка доступности для пользователей с ограничениями.

### Примеры:

навигация с клавиатуры;  
alt-тексты;  
контрастность;  
фокус на элементах;  
screen reader;  
aria-атрибуты.  
Security Testing  

Базовые проверки безопасности:  

авторизация;  
аутентификация;  
доступ к чужим данным;  
XSS;  
SQL-инъекции;  
CSRF;  
brute force protection;  
session expiration;  
права ролей;  
хранение токенов;  
маскирование чувствительных данных.  

### На собеседовании лучше сказать:

Я не позиционирую себя как security-специалист, но как QA проверяю базовые риски: доступы, роли, валидацию, обработку токенов, утечки данных и типовые уязвимости на уровне приложения.  

Performance Testing  

### Проверка производительности.

### Виды:

load testing;  
stress testing;  
spike testing;  
soak testing;  
scalability testing.
