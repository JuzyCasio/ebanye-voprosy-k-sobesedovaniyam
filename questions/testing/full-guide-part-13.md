## 58. Как тестировать кэш

### Проверки:

данные берутся из кэша;  
кэш инвалидируется после изменения;  
TTL работает;  
устаревшие данные не показываются;  
разные пользователи не видят чужой кэш;  
очистка кэша;  
поведение при недоступности Redis/Memcached;  
consistency между кэшем и БД.  

### Типичный баг:

Пользователь изменил профиль, но UI продолжает показывать старые данные из кэша.

логи читаемые;  
ошибки не теряются;  
stack trace есть там, где нужен.

## 63. Тестирование производительности

Load Testing  

### Проверка под ожидаемой нагрузкой.

### Пример:

1000 пользователей одновременно оформляют заказы.  

Stress Testing  

### Проверка за пределами нормальной нагрузки.

### Цель — понять, где система сломается.

Spike Testing  

Резкий всплеск нагрузки.  

### Пример:

После рекламной рассылки пользователи массово заходят на сайт.  

Soak Testing  

Длительная нагрузка.  

### Цель — найти утечки памяти, деградацию, накопление ошибок.

Scalability Testing  

### Проверка, как система масштабируется при добавлении ресурсов.

Метрики производительности  
response time;  
latency;  
throughput;  
RPS;  
TPS;  
error rate;  
CPU;  
memory;  
disk I/O;  
network I/O;  
DB connections;  
queue lag;  
p95/p99 latency.  

### Важно:

Среднее время ответа не всегда показательно. Лучше смотреть percentiles: p95, p99.
