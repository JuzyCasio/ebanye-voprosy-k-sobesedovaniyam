# Правила ведения базы

## Формат ответа

Каждый материал оформляется по принципу «от краткого к подробному»:

1. Формулировка вопроса.
2. Короткий ответ для собеседования.
3. Подробное объяснение.
4. Пример, если он помогает понять тему.
5. Возможные уточняющие вопросы.
6. Ссылки на связанные темы.

Необязательные блоки пропускаются, чтобы записи не превращались в формальные анкеты.

## Редакционные правила

- Начинать с прямого ответа на вопрос, а не с формального определения.
- Короткий ответ должен состоять из 2–4 простых предложений, которые можно произнести на собеседовании.
- Не использовать в коротком ответе непонятный термин без немедленного объяснения простыми словами.
- Сложные детали, исключения и особенности реализации переносить ниже короткого ответа.
- Сохранять техническую точность, но не превращать ответ в выдержку из документации.
- Расшифровывать сокращения и англоязычные термины при первом упоминании.
- Примеры Python оформлять исполняемым кодом, когда это возможно.
- Отделять общеупотребимые практики от субъективных рекомендаций.
- Не дублировать один и тот же полный ответ в разных разделах.
- Если исходный ответ сомнительный, не выдавать его за достоверный — исправить или пометить для проверки.
